ADMIN MODULE DESIGN REFERENCE
=============================

Purpose
-------
This document records the current visual design system used by the main admin
module at:

  main-system/react-frontend

Use it as the UI reference when updating the other frontend modules:

  - staff_id_managament/frontend
  - Staff_Sticker_module/react-frontend
  - student_account_module/frontend
  - Student_print_module/frontend

This is a frontend-only reference. Design work must preserve each module's
existing routes, API calls, payloads, authentication flow, state behavior, and
backend code. Do not rename API fields or alter backend contracts to match the
visual design.


1. FOUNDATION
-------------

Font
  Primary: Inter
  Fallback: system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
            sans-serif
  Source currently used: Google Fonts, weights 300, 400, 500, 600, 700.

Base page
  Body foreground: #1e293b
  Body/page background: #f8fafc (Tailwind gray-50)
  Use antialiased text rendering and border-box sizing.

Brand palette
  Primary / action: emerald-600  #059669
  Primary hover:    emerald-700  #047857
  Primary soft:     emerald-50   #ecfdf5
  Primary badge:    emerald-100  #d1fae5
  Primary text:     emerald-600 / emerald-700

  Neutral surfaces: white, gray-50 (#f9fafb), gray-100 (#f3f4f6)
  Main text:         gray-900 (#111827)
  Secondary text:    gray-600 / gray-500
  Muted/meta text:   gray-400
  Standard border:   gray-100 or gray-200

Semantic colors
  Success/active: emerald
  Warning/attention: amber (typically amber-50, amber-600, amber-700)
  Danger/delete/error: rose/red (typically rose-50/rose-600 or red-50/red-600)
  Informational: blue

Do not introduce a competing primary color for a module. Keep emerald as the
cross-module action and active-state color. Module identity may be expressed in
copy or an icon, not a new visual system.


2. TYPE SCALE AND SPACING
-------------------------

Page title
  text-xl, font-bold, text-gray-900, tracking-tight
  Supporting text: text-[11px], text-gray-400, mt-1 or mt-1.5

Section title
  text-[13px] or text-[15px], font-bold, text-gray-900
  Supporting text: text-[10px] or text-[11px], text-gray-400

Body / form controls
  Default: text-sm
  Dense management-table content: text-[11px] to text-[13px]
  Table headers: text-[10px], font-bold, uppercase, tracking-wider
  Metadata/labels: text-[10px] or text-[11px], often uppercase + tracking-wider

Standard layout
  Page wrapper: p-5 lg:p-6 min-h-full
  Header lower spacing: mb-7 or mb-8
  Standard grid gap: gap-4
  Cards/forms: p-5
  Modal content/header: p-6 / px-6 py-4

Use the compact scale deliberately. Avoid oversized titles, large controls, or
generous card padding unless the admin reference uses them for a special view.


3. SHELL AND NAVIGATION
-----------------------

Desktop sidebar
  White surface, gray-200 right border, full viewport height.
  Expanded width: w-64. Collapsed width: w-[72px].
  Header height: h-16, gray-100 bottom border.
  Navigation item: px-3 py-2, rounded-lg, text-[13px], font-medium.
  Inactive: text-gray-600; hover bg-gray-50 + text-gray-900.
  Active: bg-emerald-50 + text-emerald-700; icon emerald-600.
  Section label: text-[10px], font-semibold, gray-400, uppercase,
                 tracking-wider.
  Icons: mostly 18px navigation icons; Lucide icon set.

Responsive behavior
  Desktop tables are hidden below md; mobile presents equivalent content as
  stacked cards. Keep actions available in both views.
  Admin mobile navigation is a bottom navigation. Do not make core actions
  desktop-only.


4. CARDS, FILTERS, AND BUTTONS
------------------------------

Standard content card
  bg-white rounded-2xl border border-gray-100 overflow-hidden
  Shadow: shadow-[0_1px_3px_rgba(0,0,0,0.04)]

Statistics card
  bg-white rounded-2xl p-5 border border-gray-100
  Compact soft shadow; hover shadow deepens slightly and card moves up 2px.
  Icon tile: p-2.5 rounded-xl, typically bg-emerald-50 text-emerald-600.
  Value: text-[22px] font-bold gray-900, tracking-tight.
  Label: text-[11px] font-semibold gray-400 uppercase tracking-wider.
  Responsive grid: grid-cols-2 lg:grid-cols-4 gap-4.

Primary button
  px-4 py-2 bg-emerald-600 text-white rounded-xl
  text-[11px] font-semibold; icon + label with gap-2.
  Hover: bg-emerald-700. Active: scale-[0.97].

Secondary button
  White background, gray-300 border, gray-700 text, rounded-lg.
  Use hover:bg-gray-50 and text-sm font-medium.

Icon action buttons
  p-2 rounded-lg transition-colors, Lucide icon w-4 h-4.
  View/edit: emerald-600 and hover:bg-emerald-50.
  Delete: rose-600 and hover:bg-rose-50.
  Always retain a title/accessible label.

Search/filter card
  bg-white rounded-2xl border border-gray-100 p-5.
  Search input: rounded-xl, border-gray-200, text-[13px], py-2.5.
  Focus: ring-2 ring-emerald-500 with transparent focus border.


5. TABLES AND STATUS BADGES
---------------------------

Table container
  Place inside a white rounded-2xl bordered card with overflow-hidden.
  Allow horizontal scroll within the desktop table wrapper; do not make the
  whole page scroll horizontally.

Header row
  bg-gray-50 border-b border-gray-200.
  Cells: px-5 py-3, text-[10px] font-bold text-gray-400 uppercase
         tracking-wider.

Body rows
  Separate with divide-y divide-gray-200.
  Cells: normally px-5 py-3.5.
  Hover: bg-gray-50 (emerald-50 is also used for inventory-specific emphasis).
  Primary values: font-medium or font-semibold, gray-900.
  Secondary values: gray-600 / gray-500; IDs may use font-mono text-[11px].
  Right-align action columns.

Empty/loading state
  Keep it inside a table row/card; use centered, muted copy and enough vertical
  padding (typically py-12). Do not replace table structure with a backend or
  data-flow change.

Status badge
  Rounded-full with px-3 py-1, text-[10px] font-bold, usually a border.
  Active/success: bg-emerald-100 text-emerald-700 border-emerald-300.
  Inactive/neutral: bg-gray-100 text-gray-600/700 border-gray-300.
  Warning: bg-amber-50/100 text-amber-600/700.
  Error: bg-rose-50/100 text-rose-600/700.


6. PAGINATION
-------------

Use the existing admin pattern as the behavioral and visual reference:

  - Footer: flex items-center justify-between px-4 py-3 bg-white,
    border-t border-gray-200.
  - Left side: "Show" selector and range text in text-xs text-gray-500.
  - Page-size choices: 5, 10, 25, 50, 100.
  - Controls: first, previous, numbered pages, next, last.
  - Control size: p-1.5 rounded-md; page buttons min-w-[28px] px-2 py-1.
  - Current page: bg-emerald-600 text-white.
  - Other pages: text-gray-600, hover:bg-gray-100.
  - Disabled controls: opacity-30 and cursor-not-allowed.
  - Condense long page ranges with ellipses; preserve first and last page.

When porting this presentation, keep the target module's existing pagination
data source and API parameters unchanged. If a page is client-side paginated,
only change presentation/state wiring. If server-side paginated, map its
existing metadata to this visual layout.


7. FORMS AND MODALS
-------------------

Field presentation
  Label: block text-xs font-medium text-gray-500 uppercase tracking-wide,
         mb-1.5. Required mark uses red-500.
  Input/select/textarea: w-full px-3 py-2 border border-gray-300 rounded-lg
         text-sm.
  Focus: outline-none, ring-1 ring-emerald-500, border-emerald-500.
  Invalid: border-red-400; helper/error copy is red-500.
  Disabled: bg-gray-50 cursor-not-allowed.
  Default edit-form grid: grid-cols-1 md:grid-cols-2 gap-4; long fields span
         md:col-span-2.

Base modal behavior
  Render above all content (z-50), centered, fixed inset-0, with p-4 viewport
  clearance and a portal when supported by the target app.
  Backdrop: bg-black/40 with backdrop-blur-[2px].
  Clicking the backdrop closes standard edit/view modals when safe; close icon
  is available by default. Destructive confirmations support cancel/close too.
  Surface: bg-white, rounded-2xl, border-gray-100, shadow
           0 20px 60px rgba(0,0,0,0.12).
  Modal max height: 90vh with internal overflow-y-auto; header stays sticky.
  Entry transition: existing animate-fade-in / short 200-300ms transition.

Sizes
  sm: max-w-md       (simple confirmations)
  md: max-w-2xl      (read-only detail view)
  lg: max-w-4xl      (standard create/edit form)
  xl: max-w-6xl      (only for data-heavy content)

Modal header
  sticky top-0, white, border-b gray-100, px-6 py-4, rounded-t-2xl.
  Title: text-[15px] font-bold gray-900.
  Subtitle: text-[12px] gray-500 mt-0.5.
  Close icon: p-1.5 rounded-lg, gray-400; hover gray-100 / gray-600.

Modal actions
  Footer uses flex justify-end gap-2.5 mt-6 pt-4 border-t border-gray-200.
  Cancel is secondary. Save/confirm is emerald primary for normal writes.
  Confirmation dialogs may use amber for warning and rose for destructive
  actions. Do not submit twice: preserve each module's existing loading and
  request handling.


8. INTERACTION AND MOTION
-------------------------

  - Links/buttons use a short 150ms ease-in-out transition.
  - Cards use a subtle 200-300ms shadow/translate hover, never a large jump.
  - Page entry: fade in + translateY(6px) over about 250ms.
  - Keep scrollbar treatment thin and neutral gray; sidebar scrollbar can be
    narrower.
  - Use Lucide icons at 14-20px depending on context; do not mix icon systems
    within a module unless unavoidable.
  - Preserve keyboard focus, accessible labels, focus styles, and mobile use.


9. SAFE IMPLEMENTATION RULES FOR OTHER MODULES
-----------------------------------------------

1. Change frontend presentation components, CSS, and class names only unless a
   user explicitly requests a functional change.
2. Reuse existing target-module API services, hooks, routes, and state names.
3. Keep request URLs, methods, payload shapes, response mappings, auth tokens,
   polling, error handling, and backend migrations untouched.
4. Do not replace an existing backend pagination/search/filter implementation;
   only restyle it or adapt its existing values to the shared visual pattern.
5. Make visual changes one module at a time, then build/lint that module and
   verify its key list, modal, form, and mobile view.
6. Do not alter the current main-system admin module as part of a port unless
   explicitly requested; it is the reference baseline.
