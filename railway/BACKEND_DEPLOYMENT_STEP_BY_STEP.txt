RAILWAY BACKEND DEPLOYMENT — STEP BY STEP
==========================================

This guide deploys these four Laravel APIs from the SAME GitHub repository:

  1. main-backend
  2. account-backend
  3. staff-id-backend
  4. print-backend

AUTOMATIC GITHUB -> RAILWAY DEPLOYMENT
--------------------------------------

Railway is already connected to the GitHub main branch. In the future, use the
normal Git workflow from the repository root:

  git status
  git add <only-the-files-you-changed>
  git commit -m "Describe your change"
  git push origin main

After `git push origin main` succeeds, Railway automatically detects the new
GitHub commit and deploys the connected service. No Railway CLI deployment
command, Procfile, or local deployment script is required.

A local file save by itself does NOT deploy anything; Git must create a commit
and push it to GitHub.

Until Watch Paths are configured in every Railway service, one push can trigger
all services connected to this repository. Configure these later in each
service's Settings -> Build -> Watch Paths:

  main-backend:    /main-system/laravel-backend/**
  account-backend: /student_account_module/backend/**
  staff-id-backend:/staff_id_managament/backend/**
  print-backend:   /Student_print_module/backend/**

DO NOT deploy Staff_Sticker_module/backend. The current Staff Sticker frontend
uses account-backend's API, and the sticker backend has no API routes.


PART A — DO THIS ONCE BEFORE ANY BACKEND
-----------------------------------------

1. Make sure the latest Railway Dockerfile fix is pushed to GitHub main.

   In PowerShell:

   cd C:\DockerProjects\integrated-system

   git add main-system/laravel-backend/Dockerfile.railway staff_id_managament/backend/Dockerfile.railway Staff_Sticker_module/backend/Dockerfile.railway student_account_module/backend/Dockerfile.railway Student_print_module/backend/Dockerfile.railway

   git commit -m "Fix Railway Composer PHP version"

   git push origin main

   IMPORTANT:
   The old build failure happened because the old Composer image used PHP 8.5.
   Do not retry a backend deployment until this commit is visible on GitHub.

2. Confirm your Railway project already has a MySQL service named "MySQL".

   If its service card is named differently, that is okay. In all examples below,
   replace "MySQL" in ${{MySQL....}} with the exact database service name, or use
   Railway's variable reference picker instead of typing the value manually.

3. IMPORTANT RULES:

   - All backends use the SAME shared Railway MySQL database.
   - Every backend needs a DIFFERENT APP_KEY.
   - Every backend needs its OWN APP_URL/public domain.
   - Every backend uses port 8080 in Railway's Generate Domain dialog.
   - Do NOT manually create a PORT variable.
   - Do NOT type localhost for DB_HOST or frontend URLs.
   - Do NOT add VITE_* variables to a backend.
   - Root Directory spelling/capitalization must be exact.

Run these commands locally. Copy each result to a safe temporary note.

PART C — HOW TO CREATE ANY BACKEND SERVICE IN RAILWAY
------------------------------------------------------

Repeat this procedure for each backend in Part D:

1. Open the Railway project canvas.
2. Click + New.
3. Click GitHub Repo.
4. Select Jeyeeem21/SiaOverAll.
5. Select branch main.
6. Railway creates a service card. Close its panel if necessary.
7. Right-click the service card -> Update Info / Rename Service.
8. Enter the required service name exactly. Example: main-backend.
9. Click the service card -> Settings -> Source.
10. Click Add Root Directory.
11. Paste the exact Root Directory listed for that backend.
12. Go to Variables -> Raw Editor.
13. Paste the correct variable block from Part D.
14. Click Update Variables.
15. Go to Settings -> Networking -> Generate Domain.
16. In the "Enter the port your app is listening on" box, enter:

      8080

17. Click Generate Domain.
18. Copy the generated public domain. Example:

      main-backend-production-xxxx.up.railway.app

19. Return to Variables -> Raw Editor. Replace the APP_URL value with:

      APP_URL=https://THE-GENERATED-DOMAIN.up.railway.app

20. Click Update Variables.
21. Settings -> Deploy -> Healthcheck Path. Enter:

      /health

22. If the backend requires a volume, Settings -> Volumes -> Add Volume.
    Set Mount Path exactly to:

      /var/www/html/storage

23. Click Apply Changes, then Deploy.
24. Open Deployments -> Build Logs. Wait for a successful build/deployment.
25. Open this URL in a browser:

      https://THE-GENERATED-DOMAIN.up.railway.app/health

    Expected response:

      healthy

Do not proceed to database migration until all four backend health URLs return
healthy.


PART D — EXACT SETTINGS AND VARIABLES PER BACKEND
--------------------------------------------------

NOTE ABOUT DATABASE VALUES
--------------------------

The following uses Railway reference-variable syntax. If typing it is difficult,
click New Variable and select the database variable from the Railway picker.

  DB_HOST     = MySQL -> MYSQLHOST
  DB_PORT     = MySQL -> MYSQLPORT
  DB_DATABASE = MySQL -> MYSQLDATABASE
  DB_USERNAME = MySQL -> MYSQLUSER
  DB_PASSWORD = MySQL -> MYSQLPASSWORD


1. MAIN SYSTEM API
------------------

Service Name:

  main-backend

Root Directory:

  /main-system/laravel-backend

Volume:

  Optional. Add /var/www/html/storage only if you use uploads in Main System.

Raw Editor variable block:

  RAILWAY_DOCKERFILE_PATH=Dockerfile.railway
  APP_ENV=production
  APP_DEBUG=false
  APP_KEY=PASTE_THE_MAIN_BACKEND_KEY_FROM_PART_B
  APP_URL=https://REPLACE_AFTER_GENERATING_DOMAIN
  DB_CONNECTION=mysql
  DB_HOST=${{MySQL.MYSQLHOST}}
  DB_PORT=${{MySQL.MYSQLPORT}}
  DB_DATABASE=${{MySQL.MYSQLDATABASE}}
  DB_USERNAME=${{MySQL.MYSQLUSER}}
  DB_PASSWORD=${{MySQL.MYSQLPASSWORD}}
  LOG_CHANNEL=stderr
  LOG_LEVEL=error
  SESSION_DRIVER=database
  CACHE_STORE=database
  QUEUE_CONNECTION=database
  SESSION_SECURE_COOKIE=true

Healthcheck Path:

  /health

Generate Domain Port:

  8080

PART E — RUN MIGRATIONS ONLY AFTER FOUR BACKENDS ARE HEALTHY
-------------------------------------------------------------

For each service below: click service -> Console/Shell -> run the command.

1. main-backend:

   php artisan migrate --force

2. staff-id-backend:

   php artisan migrate --force

3. account-backend:

   php artisan migrate --force

4. print-backend:

   php artisan migrate --force

If one migration fails, STOP. Copy the full error before moving to the next
backend. Do not run the later migrations out of order.


PART F — CORS (DO THIS ONLY AFTER ALL FIVE FRONTENDS HAVE DOMAINS)
-------------------------------------------------------------------

Do not set CORS yet if frontends do not exist. Once all frontend domains are
generated, add this variable to ALL FOUR backend APIs:

  CORS_ALLOWED_ORIGINS=https://MAIN-FRONTEND-DOMAIN,https://STAFF-ID-FRONTEND-DOMAIN,https://PRINT-FRONTEND-DOMAIN,https://STICKER-FRONTEND-DOMAIN,https://ACCOUNT-FRONTEND-DOMAIN

Rules:

  - Use https://
  - No ending slash /
  - Commas only; no spaces
  - Never use localhost or railway.internal
  - Redeploy the API after changing this variable
